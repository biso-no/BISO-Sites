# Document versions, SharePoint publishing and campus filtering — design

Date: 2026-10-01
Status: awaiting review

## Goal

Governing documents (national statutes, campus local laws, code of conduct,
business regulations, communication guidelines) are adopted at general
assemblies and national meetings. Staff upload each adopted version once, in
the admin app, and it then:

1. appears on the public documents page in `apps/web`, with earlier versions
   available as history;
2. is stored in the Intranet SharePoint library, with a stable link the
   SharePoint documents page can point at permanently;
3. can be opened by people outside the tenant.

The public page is campus filtered: a selected campus shows that campus's
local laws plus all national documents; "all campuses" shows everything.

## Current state

- `documents` holds one row per document. `uploadNewVersion` replaces the
  SharePoint file in place and bumps `version_number`; no history is kept and
  the web page only shows the latest file.
- `version` is free text; `sort_order` drives list ordering.
- Uploads resolve the drive from the first entry in `SHAREPOINT_SITES`, which
  is "Finance HUB". The documents library is on the Intranet root site.
- `ORG_DOCS_ROOT` is `/Documents/Organisational Documents`; the real folder is
  `/Organisational documents` at the root of the library.
- The app registration (`Sharepoint Indexer`) has `Files.Read.All` and
  `Sites.Selected`. Reads work. A test upload on 2026-10-01 returned
  `403 accessDenied`: there is no write grant on the Intranet site.
- No sharing link is created; `sharepoint_web_url` is the internal URL.
- `listPublishedDocuments` already returns national documents plus the
  selected campus's documents, and everything when no campus is selected.

SharePoint today keeps one PDF per version (`… v11.pdf`), with
`Statutes/Previous versions` as the archive. Minor versions exist (`v7.1`,
`v3.1`).

## Design

### Version numbers

- Admin input: a fixed, uneditable `v` prefix attached to a text input that
  accepts `12` or `7.1` (`^\d+(\.\d+)?$`). Anything else is rejected by
  `documentMetadataSchema`.
- A pure helper module, `@repo/shared/utils/document-version`, exposes
  `parseDocumentVersion("7.1") → { major: 7, minor: 1 }`,
  `formatDocumentVersion({ major, minor }) → "7.1"` (minor `0` is omitted) and
  `compareDocumentVersions(a, b)`. Both apps use it.
- `documents.version` stores the formatted string without the prefix (`"12"`,
  `"7.1"`). The UI adds the `v`. `documents.version_number` is set to the major
  number so existing readers keep working.
- `sort_order` is removed from the admin form and from all ordering. The
  column stays in the schema, unused.

### Data model

New table `document_versions` (added to `packages/api/appwrite.config.json`;
pushed and types regenerated by Markus):

| Column | Type | Notes |
|---|---|---|
| `document_id` | string, required | `$id` of the `documents` row |
| `version_major` | integer, required | |
| `version_minor` | integer, required, default 0 | |
| `sharepoint_item_id` | string, required | the archived per-version file |
| `sharepoint_drive_id` | string, required | |
| `file_name` | string, required | name of the archived file |
| `file_size` | integer | |
| `uploaded_by` | string | admin user id |

Indexes: unique on (`document_id`, `version_major`, `version_minor`); key on
`document_id`. Permissions mirror `documents` (`read("any")`, writes for
Operations Unit); the web app only reads versions of published documents.

`documents` is unchanged in shape. Its SharePoint columns point at the
*current* file; `sharepoint_web_url` holds the public link when one exists.

### SharePoint layout

Root: `/Organisational documents` in the Intranet library, addressed through
`SHAREPOINT_DOCUMENTS_DRIVE_ID`. The auto-discovery fallback is removed: if the
variable is missing the upload fails with a clear configuration error instead
of writing to whichever site is listed first.

```
Organisational documents/
  <Category>/[<Campus>/]<Language>/
    <Title>.pdf                      ← current, replaced in place
    Previous versions/
      <Title> v12.pdf                ← one file per version, including current
      <Title> v11.pdf
```

Category, campus and language folder names keep the existing mapping in
`sharepoint-mapping.ts`. File names come from the document title (sanitised),
not from the uploaded file's name, so they are stable and predictable. Missing
folders are created by the path-based upload.

Because the current file is replaced in place, its item id and URL never
change. The SharePoint documents page links to it once and always shows the
latest version.

### Admin flows

`createDocument`:

1. Validate metadata, authorization and the PDF (unchanged).
2. Upload the archived file to `Previous versions/<Title> v<version>.pdf`.
3. Upload the current file `<Title>.pdf`.
4. Create an anonymous view link on the current file (best effort).
5. Insert the `documents` row and the first `document_versions` row.

`uploadNewVersion` takes a version number alongside the file:

1. Reject a version that is not greater than the latest stored version.
2. Upload the archived file, then replace the current file in place.
3. Insert the `document_versions` row; update `version`, `version_number`,
   `file_size` and `updated_by` on the `documents` row.

SharePoint writes happen before database writes. Both uploads are path based,
so retrying after a partial failure overwrites the same files rather than
duplicating them. Errors keep the existing `{ error, sharePointError }` shape.

`deleteDocument` keeps its current behaviour for SharePoint (files stay) and
also removes the document's `document_versions` rows.

The document editor shows the version history and the stored link with a copy
button, for pasting into the SharePoint page.

### Public access

`SharePointService.createAnonymousViewLink(driveId, itemId)` calls
`createLink` with `type: "view"`, `scope: "anonymous"`. On success the link is
stored in `documents.sharepoint_web_url`; it opens for tenant members and
outsiders alike. If the tenant or site forbids "Anyone" links, the internal
URL is stored instead, the upload still succeeds, and the admin UI says the
document is not externally shareable from SharePoint. The `biso.no` download
link is public regardless.

### Web

- `listPublishedDocuments` keeps its campus logic and gains a fixed ordering:
  category order, then title. It also loads `document_versions` for the listed
  documents in one query and returns them grouped per document, sorted newest
  first with `compareDocumentVersions`.
- `DocumentRow` shows `v<version>` and an expandable "Previous versions" list.
- `/api/documents/[id]/download` accepts `?version=<document_versions id>`.
  It serves that version only if it belongs to the requested published
  document; without the parameter it serves the current file as today.
- Campus filter rule, stated once and covered by a test: national-scope
  documents are always included; campus-scope documents are included when
  their campus is the selected one, or when no campus is selected.

## Manual prerequisites

1. **Write grant** for the app on the Intranet site (`Sites.Selected`, role
   `write`), done by a SharePoint admin via Graph Explorer or PnP PowerShell.
2. **External sharing**: "Anyone" links enabled for the tenant and the
   Intranet site, if SharePoint links should open for outsiders.
3. `SHAREPOINT_DOCUMENTS_DRIVE_ID` set in admin (local and production).
4. Production `SHAREPOINT_CLIENT_SECRET` updated to the secret created
   2026-10-01 (expires 2028-10-01).
5. Push the `document_versions` table and regenerate types.

## Out of scope

- Importing the PDFs already in SharePoint as history (separate backfill).
- Editing the SharePoint page itself; it is linked by hand once per document.
- Deleting SharePoint files when a document is deleted in admin.

## Testing

- `bun:test` unit tests: version parse/format/compare; folder and file-name
  mapping; campus filter rule; "new version must be greater" check.
- `bun run check-types`, plus `bun run build --filter=admin` because
  `"use server"` files change.
- Manual: create a document, upload a second version, confirm both files in
  SharePoint, the unchanged current URL, the history on the web page, and the
  campus filter for one campus and for "all".
