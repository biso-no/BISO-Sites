# Recruitment Foundation

The first recruitment foundation extends the existing jobs feature instead of introducing a separate public app.

## Surface Areas

- `apps/web`
  Candidate-facing vacancy list and detail pages stay under `/jobs`.
- `apps/admin`
  Vacancy management stays under `/jobs`, with internal application review at `/jobs/applications` and `/jobs/[id]/applications`.
- `apps/api`
  Public vacancy reads and candidate submissions run through API routes for web/native clients.
- `packages/shared`
  Shared schemas and business rules define vacancy metadata, application payload validation, and status transitions.

## API Routes

Public routes:
- `GET /api/recruitment/vacancies`
- `GET /api/recruitment/vacancies/[slug]`
- `POST /api/recruitment/vacancies/[jobId]/applications`

Admin management is handled by `apps/admin` server actions using `@repo/api/server` directly, not by calling `apps/api`.

## Data Model

- Vacancy source of truth remains the `jobs` table.
- Recruitment-specific vacancy fields are stored in `jobs.metadata`.
- Candidate submissions reuse `job_applications`.
- CV uploads are stored in the private Appwrite bucket `recruitment_resumes`.

## Vacancy Metadata Contract

The normalized metadata schema preserves legacy fields and adds recruitment-specific fields:

- `company`
- `employment_type`
- `paid`
- `short_description`
- `location`
- `application_deadline`
- `contact_name`
- `contact_email`
- `cv_required`

## Application Lifecycle

Allowed status transitions:

- `submitted -> reviewed | rejected`
- `reviewed -> interview | rejected`
- `interview -> reviewed | accepted | rejected`
- `accepted` and `rejected` are terminal

Submission rules:

- public viewing is allowed without auth
- applications require a real authenticated account
- anonymous sessions are rejected
- the vacancy must still be open and published
- duplicate submissions for the same job and applicant email are blocked
- GDPR consent is required
- CV upload is required only when `cv_required` is enabled on the vacancy

## Appwrite Migration Notes

Deploy the updated Appwrite config so the new bucket exists:

- bucket id: `recruitment_resumes`
- file security: enabled
- public permissions: none
- allowed file extension: `pdf`
- max file size: `5 MB`

Without that bucket, application submissions that include a CV will fail.
