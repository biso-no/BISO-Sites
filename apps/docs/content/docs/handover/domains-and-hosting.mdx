# Domains and hosting

this one apex.

| DNS provider | proisp.no (same as registrar) |

## DNS records to be aware of

- **A / AAAA / CNAME** for each subdomain above, pointing at the
  appropriate host.
- **MX records** for `biso.no` (handled by Microsoft 365 — see Azure AD).
  These are independent of the platform but live in the same DNS zone.
- **TXT records** for SPF, DKIM, DMARC (M365 setup) and any provider
  domain-verification tokens (Stripe, SendGrid-like services if added,
  Vipps if applicable).

## Hosting topology

The platform is provider-agnostic. Historically it has been served from
a mix of:

- **Appwrite Sites** — referenced by the `build:web:appwrite`,
  `build:admin:appwrite`, `build:api:appwrite`, `build:docs:appwrite`
  scripts in the root `package.json`.
- **Webdock** — referenced by the `WEBDOCK_API_KEY` env var. Used at
  some points for the Appwrite host and possibly the Node apps.
- **Vercel-style hosting** — supported because the apps are stock
  Next.js with `output: "standalone"`.

## SSL / TLS

Whichever provider hosts each app handles certificate issuance — usually
Let's Encrypt automatic renewals, or a provider-managed certificate.
There is no manually-managed cert in the platform.

If a cert fails to renew, the symptom is browser warnings on the
affected subdomain. Most providers auto-renew 30 days before expiry; the
failure mode is usually a DNS record having been changed.

## CDN / edge

Next.js' built-in image optimisation and static file serving handle the
edge concerns. The platform does not currently sit behind a third-party
CDN (Cloudflare, Fastly, etc.). The `next.config.ts` files allow
`appwrite.biso.no` as a remote image source — adding new image hosts
requires editing `remotePatterns` and redeploying.

## Email

The platform itself does **not** send much email. Transactional
notifications go through Appwrite Messaging (and Appwrite uses whatever
SMTP is configured at the instance level). User-facing communications
(newsletters, marketing) go through whatever tool BISO's communications
team uses — outside the scope of this docs site.
