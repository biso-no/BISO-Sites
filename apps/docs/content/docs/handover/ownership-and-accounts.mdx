### License model — important context

BISO does **not** pay for Microsoft 365 licenses. Instead, the
organisation relies on BI Norwegian Business School's tenant
licensing. The flow:

1. A new BISO staff member is a BI student, so they already have a
   Microsoft 365 license attached to their **student email**.
2. When they take a BISO role, they first activate / verify their
   license using that student account.
3. The BISO account (`name@biso.no`) is created under BISO's tenant
   (`biso.no`) and can sign in for organisational use — including the
   admin app at admin.biso.no.

This means there is no monthly Microsoft 365 subscription cost for the
~300 BISO accounts. It also means the platform's authentication is
indirectly dependent on BI maintaining its student-license programme.
If BI ever changed that arrangement, BISO would need to acquire its own
licenses. The next IT Manager should keep BI's IT contact in their
phone for this reason.

incoming person through each section and tick:

- [ ] Incoming person has tested login to every row above.

      manager).

      memberships (replaced with role accounts where possible).
- [ ] Any personal devices with cached secrets / SSH keys have been
      wiped of BISO material.

      incoming IT Manager]. Date: [FILL IN].
