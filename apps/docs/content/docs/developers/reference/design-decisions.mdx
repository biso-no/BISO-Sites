Read this when something in the code looks odd and you want to know whether it was done on purpose, or before you undo something. Most entries come from the design records in `docs/superpowers/specs/`: 28 files written between June and October 2026, each named after its date. Open the record when you need the detail. The other entries are rules written down in the `CLAUDE.md` files, which developers and coding agents follow.

A design record shows what was planned on that date. Where the code or a later record went another way, the entry says so. [Known limitations](/developers/reference/known-limitations) lists what is still wrong today.

Entries are grouped by area, newest first within each group. Rules from the `CLAUDE.md` files have no single date, so they come last in their group.

## Platform and code

- **AI runs on Anthropic (22 October 2026).** The models moved from OpenAI's GPT-5.6 family to Anthropic's Claude Sonnet 5.5 and Haiku 5.5, and the choice lives in one file, `packages/ai/src/models.ts`, which offers a `balanced` and a `fast` tier. The commit doesn't record why the provider changed. [AI](/developers/reference/ai) covers the details.
- **The api runs as one instance (30 September 2026).** When the api fulfils a membership, it clears its membership-status cache with `revalidateTag`. That only clears every copy while there's a single instance. If you ever run more than one, the other copies give stale answers for up to 60 seconds. Record: `2026-09-30-membership-status-via-api-design.md`.
- **Payments run in the api (11 September 2026).** Checkout, payment updates and the shop's postings to 24SevenOffice run in `apps/api`. The website and the BISO app ask the api, or read Appwrite, and never call Vipps, Stripe or 24SevenOffice for a payment, apart from the website's deprecated `/api/cron/reconcile-orders` route. The admin still calls the providers itself for refunds. Accounting choices, such as the sales types and voucher settings, are set in the admin and not in environment variables. Record: `2026-09-11-finago-shop-ledger-posting-design.md`.
- **All Appwrite access goes through `@repo/api`.** App code never imports `appwrite` or `node-appwrite` directly (root `CLAUDE.md`). The package is the one place that creates clients, and its `db` copies rows into plain objects so they can pass from a Server Component to a Client Component (`apps/admin/CLAUDE.md`). See [Packages](/developers/reference/packages#repoapi).
- **Server first.** Pages are React Server Components and changes go through server actions. A file is marked `"use client"` only when it needs state, effects or browser APIs (root `CLAUDE.md`).
- **Bun, one version catalogue and Turborepo.** Bun is the only package manager, because the workspaces and the shared `catalog:` versions need it. Shared versions are set once in the root `package.json` (since 5 April 2026). Turbo's remote cache is off, and the build lists every environment variable it reads, so a cached build is only reused when those values match (root `CLAUDE.md`, `turbo.json`).
- **Biome through Ultracite** formats and lints the repo, except `packages/ui` (see [Packages](/developers/reference/packages#repoui)). The house style is in `.claude/CLAUDE.md`. A few of its rules are guidance only: for example, it asks for no barrel files, but `biome.jsonc` turns that rule off.
- **No middleware in the admin or the website.** In the admin, each route-group layout, server action and route handler checks access itself (`apps/admin/CLAUDE.md`). The website removed its middleware on 17 June 2026, for the reason under [Anonymous sessions only when needed](#sign-in-roles-and-permissions) below.

## Sign-in, roles and permissions

- **Docs trust team ids, never team names (28 October 2026).** Any signed-in Appwrite user can create a team with any name, so the docs' check for private values accepts only the exact team ids the Microsoft group sync creates, plus `docs-handover` (`apps/docs/CLAUDE.md`, "Who can see values"). The admin and the api still read names. See [Auth and roles](/developers/change-it/auth-and-roles#known-issues).
- **The website's session cookie is `a_session_biso_web` (13 August 2026).** The old name, `a_session_biso`, is the cookie Appwrite itself uses for the project `biso`. Set on `.biso.no`, it reached Appwrite during the admin's Microsoft sign-in, and admin sign-in failed with `409 user_already_exists` (`apps/web/CLAUDE.md`, `apps/web/src/lib/cookie-prefs.ts`).
- **Content permissions: the admin is the only way to write content (11 August 2026).** The admin works out a person's campus and department from their teams, checks every change against that scope, and then writes with the service key. A row's own permissions only say who may read it: `read("any")` once published, nothing while it's a draft. Teams mirrored from Microsoft groups never go into a row's permissions, so a group change doesn't leave old grants behind. Ownership moved to `campus` and `department` relationship columns. Why: table-wide grants couldn't express "this campus and this department", and a broad table grant could make drafts public. The schema file still has table-wide grants on several content tables, and the script that removes them hasn't been applied. See [Data model](/developers/change-it/data-model#known-issues). Record: `2026-08-11-content-permissions-relationships-design.md`.
- **Anonymous sessions only when needed (17 June 2026).** The website used to create an anonymous Appwrite session on every first page view. Crawlers, link previews and uptime checks each made a new anonymous user, and thousands of junk accounts piled up. Now `ensureAnonymousSession()` creates one only inside actions that need it, such as the cart, and the visitor's language and campus live in cookies instead (`apps/web/CLAUDE.md`).
- **HR is a role with reach across the organisation (16 June 2026).** HR used to be treated as just another department, so HR staff couldn't see vacancies owned by other departments. HR became its own role for all recruitment, campus became a filter and never a permission, and the recruitment tables were limited to Operations Unit and HR. Record: `2026-06-16-recruitment-hr-permissions-design.md`.
- **AI fixes Microsoft departments (9 and 10 June 2026).** The free-text department field on Microsoft accounts had drifted: exact matching flagged 1109 of 1977 users. The first design matched names by similarity. The second replaced it with an AI resolver that also reads the role-based mailbox name, which says more about a person's role than the typed department, and may only answer with a department from the official list. The string matcher had proposed putting 29 people into a unit with six to nine members. Records: `2026-06-09-m365-department-remediation-design.md`, `2026-06-10-m365-department-remediation-ai-design.md`.
- **Roles come from Microsoft groups, not labels.** The group roles come from `SG-App-Campus-*` and `SG-App-Dept-*` groups, copied into Appwrite teams at each admin sign-in. The `SG-App-Role-*` groups and Appwrite user labels are no longer used for roles (`apps/admin/src/lib/roles.ts`). The one exception is `benefitseditor`, which comes from the `BENEFITS_EDITOR_EMAILS` email allow-list. [Auth and roles](/developers/change-it/auth-and-roles#roles) has the full table. The Control Committee's access to governing documents is checked by its team id (`apps/admin/src/lib/documents/access.ts`).

## Content and the page editor

- **The page editor redesign (23 October 2026).** Blocks now look like the redesigned website, pages are built from sections with up to four columns, and a page can have its own two-colour theme, checked for contrast. A published admin page replaces the coded default for a unit (`/units/<campus>/<slug>`) or a national project (`/projects/<slug>`). Every page built before was a test, so old documents aren't migrated and render empty. Why: built pages looked like a different site from the redesign around them, which blocked putting the redesign live. Record: `2026-10-23-page-editor-redesign-design.md`.
- **One place for every benefit (21 October 2026).** Every benefit is a `campus_benefits` row with a `section`. Before, the lists on the membership, students and campus pages came from text arrays on `campus_data`, copied from the old WordPress site, which only the Appwrite console could edit, while benefits made in the admin showed only in the member portal. Record: `2026-10-21-benefits-studio-design.md`.
- **Governing documents keep their versions (1 October 2026).** Staff upload each adopted version once in the admin. The website shows it with earlier versions as history, and the file is stored in SharePoint with a link that doesn't change. Before, a new upload replaced the file and no history was kept. Record: `2026-10-01-document-versions-sharepoint-design.md`.
- **Lists page on the server (3 and 7 September 2026).** Appwrite now returns the true row count, so admin and website lists page through the database, and search and filters run on the server. Before, search ran in the browser over the rows already loaded, which missed everything beyond them. Records: `2026-09-03-admin-pagination-design.md`, `2026-09-07-web-list-pagination-design.md`.
- **The website's design system (31 August 2026).** The redesign's spec is `docs/redesign/01-design-spec.md`. `apps/web/CLAUDE.md` turns it into rules: only registered colour tokens, Museo Sans and Museo Slab only, no gradients, no `backdrop-blur`, no scroll-triggered motion. Tests in `apps/web` enforce the colour and motion rules.
- **Departments get their own pages (25 August 2026).** A department's published editor page is bound to the department and served at a readable address instead of the fixed `/units/{$id}` template, whose id is a 24SevenOffice accounting number. The address became `/units/<campus>/<slug>` in the page editor redesign. Record: `2026-08-25-department-unit-pages-design.md`.
- **Blocks follow the brand, and the admin keeps its own look (21 August 2026).** The block renderer used a design system unrelated to the BISO brand, had no media queries, and showed made-up events when a data request failed. The blocks were rebuilt on the website's design. The admin looking different from the website is deliberate. Record: `2026-08-21-onbrand-page-blocks-design.md`.
- **A separate tool for the WordPress import (18 August 2026).** Old vacancies, products and orders were copied by a command-line package, `packages/wp-import`, which can run again safely because every row gets an id worked out from the WordPress record. It has no events importer: the WordPress events calendar had no events. Record: `2026-08-18-wordpress-content-import-design.md`.
- **Translation after saving (11 August 2026).** One shared service translates between Norwegian and English for pages, news, events, vacancies, products, benefits and announcements. It runs after an explicit save or publish, in the background, so authors don't wait for the model. Autosave never translates, to avoid cost and stale writes. Record: `2026-08-11-content-auto-translation-design.md`.
- **News gets a studio and shares the jobs editor (29 July and 10 August 2026).** News moved from a single form to a full-screen studio like the vacancies one. Jobs and news then share one block-based editor, with images, video, audio and files stored in the existing `media` bucket. Files aren't deleted when a block is removed, because published or older content may still point at them. Records: `2026-07-29-news-publishing-studio-design.md`, `2026-08-10-news-shared-media-editor-design.md`.
- **A shorter admin menu and ⌘K (9 July 2026).** A global admin saw about 20 items in the sidebar. It was cut to about eight, with ⌘K as the quickest way to reach anything. Who can see what (`NAV_ACCESS`) didn't change. Record: `2026-07-09-admin-nav-and-command-palette-design.md`.
- **`departments` is the list of units, and `active` doesn't mean public.** The table mirrors 24SevenOffice's chart of accounts, so operating ledgers and national bodies are active but have no public page. The website also filters with `isPublicUnit` (`apps/web/CLAUDE.md`).
- **The website's cached readers throw.** A function marked `"use cache"` must throw on failure. If it returned an empty list instead, that empty result would be cached and served for the whole cache window (`apps/web/CLAUDE.md`).

## Membership, shop and accounting

- **Membership status through the api (30 September 2026).** The website and the api used to check 24SevenOffice separately, each behind its own 10-minute cache that nothing cleared after a purchase, so a student who had just paid could be told they weren't a member. Now only the api works out the status, and the website asks it with the student's token. A purchase made on the website or in the BISO app shows at once. One made in BI's own student app shows within 60 seconds. Record: `2026-09-30-membership-status-via-api-design.md`.
- **The roster is a nightly copy, and the plan list comes from 24SevenOffice (29 September 2026).** The admin's member list is a display-only snapshot, rebuilt by the member-roster-sync function, because 24SevenOffice's member call takes about 72 seconds and can't be paged. The `memberships` plan list is copied from 24SevenOffice too: about 1,490 paying members held plans that had no row, so they counted as non-members. Records: `2026-09-29-member-roster-design.md`, `2026-09-29-membership-catalog-design.md`.
- **A member pass that can't be copied (17 September 2026).** The pass has a live visual and a QR code signed by the server that changes every 30 seconds, so a screenshot or a recording fails a scan. Every scan is checked live against 24SevenOffice. The app reaches the pass through the api, and scanning rights are kept in `member_pass_scanners`. Records: `2026-09-17-member-pass-design.md`, `2026-09-17-member-pass-app-api-design.md`, `2026-09-17-member-pass-app-contract.md`.
- **Every paid shop order goes to the ledger (11 September 2026).** Each paid order becomes one voucher in 24SevenOffice. That replaced a monthly booking done by hand from a WordPress export. Creating customers and sales orders in 24SevenOffice was considered and rejected. Membership sales stay invoices. Record: `2026-09-11-finago-shop-ledger-posting-design.md`.
- **Refunds have their own tables (8 September 2026).** Refunds for Vipps and Stripe are recorded in `order_refunds` and `order_refund_lines`. Each refund row is written before the provider is called, so a crash halfway leaves a record. Before this, nothing could make a refund. Record: `2026-09-08-order-refunds-design.md`.
- **24SevenOffice decides who is a member (12 August 2026).** Membership is never stored as a state in Appwrite. The website is a backup way to buy, next to BI's own student app, and a buyer must be signed in with a linked BI student account. Record: `2026-08-12-membership-purchase-design.md`.

## The BISO app and notifications

- **Update prompts managed in the admin (21 October 2026).** The minimum and recommended app versions are stored in the `app_versions` table, edited in the admin and served by the api. Why: nothing in the app could reach an old install remotely, and the Flutter app had lost the update prompt the previous app had. Record: `2026-10-21-app-update-prompt-design.md`.
- **One push topic per language and campus (20 October 2026).** Appwrite sends the same text to every device on a topic, and pushes that the app translates itself are unreliable on iOS. So each audience exists once per language, 50 topics in all, and each phone subscribes in one language. New events, news and vacancies send their push automatically, through the content-notifier function. Record: `2026-10-20-push-notifications-design.md`.

## The docs

- **A guide for staff and a handover for developers (27 October 2026).** The old docs were wrong in places that mattered and had drifted from the code within five months. The new docs have two areas. Each page names the code it describes in `covers`, and a check on pull requests warns when that code changes without the page. Private details show only after sign-in and never appear in the public repo or the static site. Record: `2026-10-27-docs-rework-design.md`. `apps/docs/CLAUDE.md` holds the rules.
