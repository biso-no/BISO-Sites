# Drafts

The **Drafts** screen is an aggregated view of everything in the admin app that has been started but not yet published. Pages, jobs, and events all show up here whenever their status is **draft**.

It exists to stop work from being forgotten. Instead of opening Pages, then Jobs, then Events and checking each list for unfinished work, you open one screen and see all of it.

It is available to global admins and campus admins.

## What you see

Each row shows:

- The **title** of the draft.
- Its **content type** (page, job, or event).
- The **campus** it belongs to.
- The **department** that owns it (if applicable).
- The **last edited** date and who edited it.
- A quick **Open** action to jump into the editor.

The list is sorted by most recently edited by default, so the things most likely to be picked up again rise to the top.

## Campus scoping

Drafts is campus-aware. A campus admin sees only their own campus's drafts. A global admin sees everything by default, but can narrow the list using the [campus switcher](/docs/admin-handbook/campus-context).

## What you can do

The Drafts screen is intentionally simple — it is a launchpad, not an editor.

- **Open** a draft to continue working on it in its native editor.
- **Quick-publish** a draft that is already ready, without going through the editor first. The button only appears when you have permission to publish that type of content; sensitive content types may route through [Approvals](/docs/admin-handbook/approvals) instead.
- **Filter** by content type, campus, or department to focus the list.

## Why something might be missing

- The item isn't actually in `draft` status. If it's published or archived, it won't appear here.
- You don't have access to its campus. Switch campus context if you are a global admin.
- It's a content type Drafts doesn't aggregate (for example shop products or benefits). Use the area's own list view for those.

## Tips

- Make a habit of checking Drafts at the end of the week. If something has been sitting for 14 days, decide: finish, archive, or delete.
- If the same person keeps leaving long-standing drafts, gentle nudges go a long way. The "last edited by" column makes that easy to spot.
- For drafts that are ready but need someone else's sign-off, use **Submit for approval** from the editor — it will move into the [Approvals](/docs/admin-handbook/approvals) queue.

## Related screens
