# Environment variables

This page is the canonical list of every environment variable the platform
reads. If you're standing up a new environment (staging, replacement
hosting, etc.) you need every variable on this page to match the app you're
configuring.

## Rules

- `NEXT_PUBLIC_*` is the only prefix that crosses to the browser. Everything
  else is **server-only** — never reference it from a Client Component.
- New build-time env vars **must** be added to `turbo.json#tasks.build.env`,
  or Turborepo will treat them as undeclared inputs and silently produce a
  miscached build. This is the single most common operational footgun.
- Secrets do not belong in git. Use the hosting provider's secret manager.
- Each app has its **own** session cookie name (`APPWRITE_SESSION_COOKIE`).
  `web` uses `a_session_biso`; `admin` uses `a_session_biso_admin`. Mixing
  them logs users out across the platform.

## `apps/web`

The public site.

### Public (bundled into the browser)

| Variable | Purpose |
|----------|---------|
| `NEXT_PUBLIC_APPWRITE_ENDPOINT` | Appwrite REST endpoint, e.g. `https://appwrite.biso.no/v1` |
| `NEXT_PUBLIC_APPWRITE_PROJECT` | Appwrite project ID |
| `NEXT_PUBLIC_BASE_URL` | The site's own canonical URL, e.g. `https://biso.no` |
| `NEXT_PUBLIC_API_BASE_URL` | The base URL of the `apps/api` service |

### Server-only

| Variable | Purpose |
|----------|---------|
| `APPWRITE_API_KEY` | Service key for `createAdminClient()` calls |
| `APPWRITE_SESSION_COOKIE` | Set to `a_session_biso` |
| `APPWRITE_BUCKET_ID` | Default storage bucket for web uploads |
| `APPWRITE_CAMPUS_BOARD_FUNCTION_ID` | Appwrite Function ID for campus board operations |
| `OPENAI_API_KEY` | OpenAI for site-side AI features |
| `SHAREPOINT_CLIENT_ID` / `SHAREPOINT_CLIENT_SECRET` / `SHAREPOINT_TENANT_ID` | Graph app credentials |
| `SHAREPOINT_SITES` | Comma-separated SharePoint site IDs |
| `VIPPS_CLIENT_ID` / `VIPPS_CLIENT_SECRET` | Vipps OAuth client |
| `VIPPS_CALLBACK_TOKEN` | Webhook auth token |
| `VIPPS_MERCHANT_SERIAL_NUMBER` | MSN issued by Vipps |
| `VIPPS_SUBSCRIPTION_KEY` | Vipps API subscription key |
| `VIPPS_TEST_MODE` | `true` in non-prod, `false` in prod |
| `STRIPE_PUBLISHABLE_KEY` / `STRIPE_SECRET_KEY` | Stripe keys |
| `STRIPE_WEBHOOK_SECRET` | Used to verify Stripe webhook signatures |
| `AZURE_APP_ID` / `AZURE_TENANT_ID` | Azure AD application identity |
| `AZURE_CERT_THUMBPRINT` / `AZURE_CERT_PASS` | Certificate-based auth to Graph |
| `AZURE_ORG` | Azure DevOps / Graph org name |
| `WEBDOCK_API_KEY` | Webdock API access (only if hosted on Webdock) |
| `PINECONE_API_KEY` / `PINECONE_INDEX_NAME` | Pinecone vector store |
| `CRON_SECRET` | Bearer token for `/api/cron/cleanup-reservations` |

> **Payment credentials are now admin-managed.** Vipps/Stripe credentials and the
> per-provider test/live mode are configured in the admin portal under
> **Settings → Platform → Payment providers** (`/payment-settings`) and stored
> encrypted in the `payment_settings` table. The `VIPPS_*` / `STRIPE_*` vars
> above are the **fallback**, used only when no managed row exists (or its active
> credential set is incomplete), so nothing breaks before the DB config is filled
> in. `VIPPS_CALLBACK_TOKEN` stays env-only (it has no managed column).

## Where these need to live

| Environment | Where the values go |
|-------------|----------------------|
| Local dev | `apps/<app>/.env.local` (gitignored) |
| Production | **Appwrite Sites env-var UI**, configured per site. This is the only place production values live. |
| CI (GitHub Actions) | Repository variables (`APPWRITE_ENDPOINT`, `APPWRITE_PROJECT_ID`, `WEB_SITE_ID`, `ADMIN_SITE_ID`, `API_SITE_ID`, `DOCS_SITE_ID`) + the `APPWRITE_API_KEY` secret. Nothing else. |

<Callout type="warning">
**Open continuity risk**: production env values exist only inside
Appwrite Sites today. There is **no off-Appwrite backup** — no
password manager, no sealed file in a private repo, no second copy in
1Password. If the Appwrite project is lost or wiped, every secret has
to be re-issued from each provider.

Recommended remediation (also called out in
[Handover / Ownership and accounts → Secrets vault](/docs/handover/ownership-and-accounts#secrets-vault)):
provision a password manager for BISO IT and store one
production-env entry per app (`web`, `admin`, `api`, `docs`). Update
each entry whenever you rotate a key.
</Callout>

## When you add a new env var

1. Read it in code via `process.env.MY_NEW_VAR`.
2. If it's accessed during `next build` (i.e. anywhere outside a request
   handler), add it to `turbo.json#tasks.build.env`.
3. Document it on this page.
4. Add the production value to the hosting provider's secret manager.
5. Add the dev value to your local `.env.local`.
6. If it's a secret, add a rotation note to
   [/docs/operations/secrets-and-keys](/docs/operations/secrets-and-keys).
