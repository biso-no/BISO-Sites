# BISO Sites

This is the documentation for the **BI Student Organisation (BISO)** digital
platform: the public website at [biso.no](https://biso.no), the internal admin
CMS, the JWT-authenticated API service that powers them, and all the shared
code that holds the whole thing together.

The platform is a single [Turborepo](https://turbo.build) monorepo with four
Next.js apps and nine shared packages, backed by a single
[Appwrite](https://appwrite.io) project. It was built and is maintained by
BISO's IT function.

## Who these docs are for

These docs serve two audiences side-by-side. Pick the path that matches you.

### I administer the platform

You work for BISO and use the admin app to publish pages, run recruitment,
manage the shop, approve content, or look after members. You probably aren't
a developer.

Start with the [**Admin Handbook**](/docs/admin-handbook) for a tour of every
screen in the admin app, then dip into the [**Public Website**](/docs/public-website)
section to understand what students see.

### I'm maintaining or extending the code

You are taking over from the previous IT Manager, you're a consultant brought
in for a piece of work, or you're an internal developer adding a feature.

Start with the [**Architecture**](/docs/architecture/overview) overview to
get the big picture, then [**Developing**](/docs/developing) for setup and
conventions. The [**Packages**](/docs/packages), [**Integrations**](/docs/integrations),
and [**Operations**](/docs/operations) sections are the day-to-day reference.

If you're literally inheriting the platform, read [**Handover**](/docs/handover)
first — it explains what accounts exist, who owns what, and the conscious
trade-offs the original author made.

## The stack at a glance

- **Frontend**: Next.js 15 (App Router, React Server Components) + React 19
- **UI**: Tailwind CSS + Radix UI primitives in `@repo/ui`
- **Page editor**: In-house block editor `@repo/editor` (built on `@dnd-kit`,
  `immer`, `zustand`). Replaced Puck in 2025.
- **Backend**: Appwrite — auth, database (TablesDB), storage, functions, teams
- **Auth**: Microsoft / Azure AD OAuth + Appwrite anonymous sessions for the
  public site
- **Payments**: Vipps MobilePay (primary), Stripe (secondary)
- **AI**: Anthropic Claude (page editor copilot, admin assistant, resume
  screening) + OpenAI (translation, expense OCR)
- **External systems**: Microsoft 365 / Graph, SharePoint, 24SevenOffice
  (Finago), Pinecone, Entur (Norwegian public transit)
- **Package manager**: Bun 1.3.1 (workspaces + `catalog:` protocol)
- **Build**: Turborepo

## A note from the original author

> This platform exists because BISO needed a digital home that the organisation
> itself owned and could iterate on. It replaced a patchwork of WordPress
> sites, hand-built signup forms, and spreadsheet-driven membership tracking.
>
> The organisation has decided not to employ a permanent IT Manager going
> forward, so these docs are written to be **complete**: not just "how the
> code is laid out", but the operational knowledge a new person — or an
> external consultant — needs to keep things running and to extend the
> platform safely.
>
> If something in the docs is wrong, it's a bug. Fix it in `apps/docs/content/`
> and open a PR.
