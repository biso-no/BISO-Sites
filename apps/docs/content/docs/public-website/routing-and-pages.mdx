# Routing and pages

The public site uses Next.js App Router. Every URL maps to a folder under `apps/web/src/app/`. Folders wrapped in parentheses are **route groups** — they don't appear in the URL but let us share a layout across a set of pages.

There are three route groups on the public site:

| Group | Layout does | Used for |
|-------|-------------|----------|
| `(public)` | Fetches membership status server-side, renders the public header/footer. | Anything an anonymous visitor can reach. |
| `(protected)` | Calls `getLoggedInUser()` and triggers `unauthorized()` if there's no real account. | Profile, applications, expense portal. |
| `(auth)` | Just renders the login surface. | `/auth/login` and the OAuth/magic-link/invite handlers. |

The 401 UI for protected routes lives at `src/app/unauthorized.tsx` and is shown automatically when `unauthorized()` is called (Next.js `authInterrupts` is enabled).

## Public routes

These are reachable without logging in. Anonymous visitors get an Appwrite session via middleware before they ever see a page — see [Authentication and sessions](/docs/public-website/authentication-and-sessions).

### Landing and editor-built pages

| Route | What's there |
|-------|--------------|
| `/` | Homepage. |
| `/[...slug]` | Catch-all for editor-built pages — anything an editor publishes in the admin app shows up here. |

The catch-all calls `getPage(slug, locale)` from [`@repo/api/page-builder`](/docs/packages/api), filters for documents that are both **published** and have visibility set to **public**, and then renders them with the block editor's read-only render entry point. Anything else 404s. This is how pages like `/about/history` or `/business-hotspot` exist as URLs without anyone touching the codebase — they're rows in Appwrite.

For the admin side of this, see [Admin Handbook → Pages](/docs/admin-handbook/pages).

## Protected routes

These require a real (non-anonymous) account. The `(protected)/layout.tsx` calls `getLoggedInUser()` and triggers Next's `unauthorized()` if the visitor doesn't have one. The 401 page invites them to log in.

| Route | What it does |
|-------|--------------|
| `/profile` | The signed-in user's profile, locale preference, etc. |
| `/applications` | The user's own job applications and statuses. |
| `/fs` | Expense / reimbursement portal — list of the user's expense claims. |
| `/fs/new` | Start a new expense with OCR receipt upload. |
| `/fs/[id]` | View or edit a single expense. |

The expense portal is documented in [Expense portal](/docs/public-website/expense-portal).

| Route | Purpose |
|-------|---------|

| `/auth/callback` | OAuth callback handler. |

## Middleware

All routing is filtered through `apps/web/src/proxy.ts` (exported as `proxy`) before a page renders. The matcher excludes `/api/*`, `_next/*`, images, and favicons. If the visitor has no session cookie, the middleware redirects to `/api/auth/anonymous?redirect=<original-url>` which mints an anonymous Appwrite session and sets the cookie. See [Authentication and sessions](/docs/public-website/authentication-and-sessions) for the cookie name and domain rules.

## Legacy stubs

`apps/web/appwrite.json` and `apps/web/database.json` are leftover stubs from an earlier iteration of the platform. The real Appwrite schema lives in `packages/api/appwrite.config.json` — see [Architecture overview](/docs/architecture/overview). Don't edit the stubs.
