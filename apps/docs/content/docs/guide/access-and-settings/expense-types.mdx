<BeforeYouStart>

## Before you start

- Only global admins see this page. In the sidebar, open **Utlegg** (Expenses) and choose **Innstillinger** (Settings). The page is headed **Innstillinger for utlegg** (Expense settings), with one tab, **Typer** (Types).
- Each type books to one ledger account in 24SevenOffice, and the account list comes from the chart of accounts synced from there. Choose **Synkroniser kontoer fra Finago** (Sync accounts from Finago) first if you have added an account in 24SevenOffice that isn't in the list. You see **Synkroniserte {count} kontoer** (Synced {count} accounts), where {count} is the number of accounts. If some accounts couldn't be saved, you see **Synkroniserte {count} kontoer, {failed} feilet** (Synced {count} accounts, {failed} failed): sync again. If the sync fails, you see **Kunne ikke synkronisere kontoer** (Could not sync accounts).
- Only active accounts from 4000 to 7999 can be chosen.
</BeforeYouStart>

## Steps

<Steps>
<Step title="Load the missing starting types">

The platform comes with a starting list of 22 types. While any of them is missing from the table, the page shows **Last inn {count} manglende starttyper** (Load {count} missing starting types), where {count} is how many are missing. With no types at all, it also says **Ingen utleggstyper ennå. Last inn starttypene for å komme i gang.** (No expense types yet. Load the starting types to begin.). Choose the button.

You see **Startlisten er lastet inn: {created} lagt til, {skipped} fantes fra før** (Starting list loaded: {created} added, {skipped} already there). Each type of the list comes with an account, a Norwegian name and a note for the AI. A type that already exists is left as it is, with your changes. The button goes away once every starting type is there.

An earlier version of the admin may already have added four types: **Travel**, **Social event**, **Academic event** and **Other**. The button leaves them as they are. Unless someone has changed them since, two of them book on other accounts than the starting list: **Academic event** on 7315 instead of 7305, and **Other** on 7790 instead of 6555. None of the four has a Norwegian name. To set them up like the starting list, change each one in its row (see [Edit a type](#edit-a-type)):

- **Academic event**: pick account 7305, and set **Rekkefølge** (Order) to 6.
- **Other**: pick account 6555, and set **Rekkefølge** (Order) to 21, so it is listed last.
- **Social event**: set **Rekkefølge** (Order) to 5.
- All four: fill in **Norsk navn** (Norwegian name): **Reise**, **Sosialt arrangement**, **Faglig arrangement** and **Annet**.

</Step>
<Step title="Add a type">

The last row of the table is empty. Fill it in and choose **Legg til type** (Add type):

- **Navn** (Name): the English name. It is required.
- **Norsk navn** (Norwegian name): the name to show when the language is Norwegian. Leave it empty and the English name is used.
- **Konto** (Account): see the next step.
- **Skattekode** (Tax code): filled in from the account when you pick one. See the next step.
- **Notat til AI** (Note for the AI): one sentence on what belongs in this type, for example what kind of receipts it is for and what it is not for. The receipt scan reads it when it picks a type.
- **Spør om anledning og deltakere** (Ask for occasion and attendees): tick it when a receipt of this type needs an occasion with it, such as a social event or a meeting. On the website the student is then asked **Hva var anledningen, og hvem var det for?** (What was the occasion, and who was it for?) and can't submit without an answer. The app doesn't ask yet. A reimbursement from the app goes through with a note for the approver that the occasion is missing.
- **Aktiv** (Active): ticked means students and the AI can use the type.
- **Rekkefølge** (Order): a number. Types are listed from the lowest.

You see **Lagret** (Saved). If it fails you see **Kunne ikke lagre** (Could not save), and **Velg konto** (Choose account) if you haven't chosen an account. A new type gets a short identifier made from its English name, and it never changes.

</Step>
<Step title="Pick the account">

Choose the button in **Konto** (Account). A list opens: search by number or name in **Søk på nummer eller navn** (Search by number or name), and choose the account. With no match you see **Fant ingen konto** (No matching account).

Picking an account fills in **Skattekode** (Tax code) with the account's tax code. You can change it, and the tax code you save is the one receipts of the type are booked with. If you empty the field, a new type gets the account's tax code. An edited type then keeps its own tax code, or takes the new account's if you changed the account.

</Step>
<Step title="Edit a type">

Change the fields in the type's row and choose **Lagre** (Save). You can change the names, the account, the tax code, the note, the occasion setting, **Aktiv** (Active) and the order. You can't change a type's identifier.

</Step>
<Step title="Deactivate a type">

Untick **Aktiv** (Active) on the type and choose **Lagre** (Save). The type is no longer offered, and the AI no longer picks it. Receipts already submitted with it keep it. There is no button to delete a type.

If you deactivate every type, students have nothing to pick and can only write their own text. The starting list is used only while the table is empty, not when every type in it is inactive.

</Step>
</Steps>

<WhatHappensNext>

## What happens next

- When a student uploads a receipt, the AI picks one of the active types for it. It reads the **Notat til AI** (Note for the AI), the English name and what similar receipts were booked as before.
- The AI learns from booked receipts only once the platform books reimbursements in 24SevenOffice itself. Until the first ones are booked, it has only the names and the notes to go on.
- At the moment a reimbursement is submitted, the receipt's type, its account and its tax code are fixed. A changed account applies to reimbursements submitted after you save, not to ones already submitted.
- When a reimbursement is booked, what it was booked as is kept, without the student's name, and helps the AI with later receipts from the same shop.
- Every create, change and starting-list load is written to the audit log with your account.
</WhatHappensNext>

## What the student sees

- A student never sees an account number, only the names of the types. In Norwegian they see **Norsk navn** (Norwegian name) when the type has one.
- On the website, each receipt with an amount has a type picker, in the receipt list and in the detail pane (**Kostnadstype**, Cost type). That includes a bank statement uploaded on its own. A bank statement attached to a receipt only backs up that receipt's amount and has no picker. The picker lists the active types in your order and has a search field, **Søk i typer…** (Search types…). When the AI is on and sure enough, it has picked a type already and the type is marked **AI**. A screen reader reads the mark as **Valgt av AI** (Picked by AI). Otherwise the receipt says **Velg type** (Choose a type).
- If nothing in the list fits, the student can write their own text and choose **Bruk «{text}»** (Use "{text}"). Enter keeps what they typed unless it is exactly the name of a type. Arrow keys or hovering pick a suggestion instead. The AI then picks the account for the text. When the student opens the picker again, the search field starts with their text.
- The student can't submit until every receipt that needs a type has one. Next to the button it says why: **Velg type for alle kvitteringene** (Choose a type for every receipt). Pressing the button takes them to the first receipt that still needs a type.
- If a type has **Spør om anledning og deltakere** (Ask for occasion and attendees) ticked, the student is asked **Hva var anledningen, og hvem var det for?** (What was the occasion, and who was it for?), and the AI fills in a suggestion when the receipts make the occasion evident. Under a suggestion it says **Foreslått ut fra kvitteringene. Sjekk og endre om nødvendig.** (Suggested from your receipts. Check it and change it if needed.) until the student changes the text. Next to the submit button it says **Fyll inn anledningen og hvem det var for** (Fill in the occasion and who it was for) until the question is answered. Pressing the button without an answer takes the student to the question, which then says **Svar på dette før du sender inn** (Answer this before you submit).
- If the department has a published event within seven days of a receipt date, the student is asked **Var dette til {event}?** (Was this for {event}?) and answers **Ja** (Yes) or **Nei** (No).
- Under a receipt the student may see a notice, for example **Kvitteringen mangler dato** (No date on the receipt), or **Ser ut som en kvittering som allerede er sendt inn** (Looks like a receipt already submitted). They only warn, and don't stop the submission.
- When every receipt has a type, the website writes the general description for the reimbursement, once the student has paused for a moment. It never rewrites text the student has edited.
- A type the student chose or accepted on the website stands. The AI doesn't replace it. If the student reopens a draft after you deactivated a type it used, that receipt says **Velg type** (Choose a type) again: a reimbursement isn't booked on a deactivated type. A receipt with the student's own text keeps it.
- The app is an older client. Its choice is only a default. When the AI is on and it picks a different type at a confidence of 0.8 or more, it replaces the app's choice, and a note that the type was replaced is stored with it.
- No screen shows the approver notes yet.

## Common mistakes

- Renaming a type to mean something else. Receipts booked earlier, and what the AI has learned from them, stay under that type. Add a new type and untick **Aktiv** (Active) on the old one.
- Picking an account without checking its tax code in 24SevenOffice. Receipts of the type are booked with that tax code.
- Leaving **Notat til AI** (Note for the AI) empty on types that sound alike. The AI then has only the names to go on and picks less sure.
- Not syncing the accounts after adding one in 24SevenOffice. It won't be in the list.
- Expecting a changed account to fix a reimbursement that is already submitted. It applies to new submissions only.
- Expecting **Last inn {count} manglende starttyper** (Load {count} missing starting types) to update types that already exist. It only adds the missing ones. Change an existing type in its row.
