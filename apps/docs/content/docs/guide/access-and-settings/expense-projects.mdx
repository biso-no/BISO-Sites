<BeforeYouStart>

## Before you start

- A project is a Finago project, for example a yearly event. A receipt can be booked on one, so the cost shows up under that project in 24SevenOffice.
- Only global admins see the **Prosjekter** (Projects) tab. In the sidebar, open **Utlegg** (Expenses), choose **Innstillinger** (Settings), then **Prosjekter**.
- The list comes from Finago. It is brought up to date every night, and you can start it yourself (see below).
</BeforeYouStart>

## Steps

<Steps>
<Step title="Sync the projects from Finago">

Choose **Hent prosjekter fra Finago** (Sync projects from Finago). You see **Hentet \{count} prosjekter** (Synced \{count} projects) when everything was fetched. If time ran out you see **Delvis hentet (\{count} prosjekter). Den nattlige kjøringen fullfører resten.** (Partly synced. The nightly run finishes it.) Nothing is lost: the next run continues from where this one stopped.

If you see **En henting pågår, eller startet nettopp** (A sync is already running, or just started), wait a few minutes. A run that started less than 5 minutes ago blocks a new one. If it fails you see **Kunne ikke hente prosjekter** (Could not sync projects).

The sync reads Finago's projects and about two years of bookings on the cost accounts (6000 to 7999, and the accounts the expense types use). From that it works out which departments use which project. **Siste fullstendige henting** (Last full sync) shows when it last finished completely.

A project that Finago has deactivated stays in the list as inactive when it has booking history. It is never deleted here.

</Step>
<Step title="Read the list">

Projects are grouped by series, so a yearly event is listed with all its years. Each row shows the name, the year, which departments use it (**Brukt av**), the first and last booking and the busiest day (**Første postering**, **Siste postering**, **Travleste dag**). Use **Avdeling** (Department) to show one department's projects.

</Step>
<Step title="Set the date of an event">

In **Arrangementsdato** (Event date), pick a date and choose **Lagre** (Save). **Fjern** (Clear) removes it. The date you set wins over every other source, so use it when the system's guess is wrong or the event hasn't been booked yet. You see **Arrangementsdato lagret** (Event date saved) or **Arrangementsdato fjernet** (Event date cleared).

Without a date from you, the system uses the event on the website, then a month in the project's name (it counts as the 15th), then the usual day that past editions were booked around.

</Step>
<Step title="Set a project on a receipt">

Open the reimbursement and choose **Rediger** (Edit) on a receipt. In **Prosjekt** (Project), choose **Velg prosjekt** (Choose project). The department's own projects come first, then **Andre prosjekter** (Other projects), and **Ingen** (None) clears it. Search with **Søk på navn** (Search by name). A department's projects are those it booked on in the last 24 months, plus newer years of the same series.

Choose **Bruk på alle kvitteringer** (Apply to all receipts) to set the same project on every receipt of the reimbursement. You see **Prosjekt satt på \{count} kvitteringer** (Project set on \{count} receipts). Every change is written to **Historikk** (History) as **Endret prosjekt fra … til …** (Changed project from … to …).

</Step>
</Steps>

<WhatHappensNext>

## What happens next

- When the reimbursement is booked, the project goes on the receipt's cost line and on the payout line (account 2400). Payout lines are split by date and project, so receipts with different projects get a line each.
- The approvers see the project on their Teams card, in the approval email and on the web approval page. When every receipt has the same project it is shown once. Receipts with no project show **none**.
- The examples the AI learns from remember the project of a booked receipt.
- The AI does not choose projects yet. Today a project is only set by a person.
</WhatHappensNext>

## What the student sees

Nothing. Students never see projects, in the website or the app.

## Common mistakes

- Expecting a brand-new project to be listed at once. Sync from Finago first, or wait for the nightly run.
- Setting the project too late. An approved reimbursement can't be edited, so set it before the last approval.
- Expecting a deactivated Finago project to disappear. It stays, marked inactive, because bookings refer to it.
