# Settings

The **Settings** screen is where global admins configure the platform itself: defaults that apply to everyone, notification rules, integrations to outside systems, and the teams that drive permissions inside the app.

Settings are global-admin only. Campus admins and department users don't see this screen in the sidebar.

## Layout

The screen is divided into sections you can switch between using the tabs at the top.

### General

Platform-wide defaults that don't belong to any one campus.

- **Locale** — default language for newly created content (typically Norwegian, with English as a secondary option).
- **Timezone** — used when the app needs to display "today" or schedule something. Almost always Europe/Oslo.

### Notifications

Controls who gets pinged about what. Each notification type has its own toggle:

- **Job applications** — notify when a new application is submitted.
- **Drafts** — notify when a draft is created or updated.
- **System alerts** — notify when a background job or integration fails.

You can turn individual categories on or off without affecting the others.

### Integrations

A list of external systems the admin app talks to. For each one you can see whether it is currently connected and run a quick connection test.

| Integration | What it's used for |
|-------------|-------------------|
| **24SevenOffice** | Finance and CRM data sync. |
| **Vipps MobilePay** | Payments from the public site. |
| **SharePoint** | Document storage and shared files. |

A green status means the last check succeeded. A red status means the integration needs attention — usually a refreshed API key or a re-authorisation. Click **Test connection** to retry without leaving the page.

### Security

Platform-level security settings: session length, who can reach the IT screens, and other safety nets that protect sensitive data. Most BISO setups leave these at the defaults.

### Team management

The teams that exist inside Appwrite and are used to grant access to specific queues — for example which team can approve campus-board changes, or which team can read a given submissions topic. From here you can create a team, rename it, and add or remove members. Changing a team membership takes effect immediately on the next page load for that user.

### App versions

Decides which versions of the BISO app students can keep using. iPhone and Android each have their own two fields, because a release usually reaches Google Play before Apple has approved it.

- **Minimum version** — anyone on an older version is blocked with a "Time to update" screen until they update. Use it when an old version must stop working, for example after a change that breaks it.
- **Recommended version** — anyone on an older version gets a popup asking them to update. They can tap "Not now", and the popup stays away for three days for that version.

Versions are written as three numbers separated by dots, like `2.4.0`. Leave a field empty to turn that check off. The recommended version can't be lower than the minimum.

A few things to know before you save:

- **Set the Android minimum only after a 100% rollout on Google Play.** During a staged rollout some students can't get the new version yet, and a minimum above what they can download blocks them with nothing to update to.
- **On iPhone, the page shows the version live in the App Store** and warns you if you type a higher one. Wait until Apple has released the version before you set it.
- **Only app builds that include this feature can be prompted.** Versions released before it never see the screen or the popup, whatever you set here.
- Students only see a change when the app next checks, usually the next time they open it.

## Changes are audited

Every change you make in Settings is written to the [Activity](/docs/admin-handbook/activity) log so other global admins can see when something changed and who changed it. If a colleague is confused why the platform behaves differently to last week, Activity is the first place to look.

## When to escalate to engineering

A few situations are not solvable from Settings alone:

- Adding a brand-new integration that doesn't appear in the list.
- Changing the rules that decide who is a campus admin (those live in Azure AD groups — see [Roles and permissions](/docs/admin-handbook/roles-and-permissions)).
- Adjusting how a Settings screen itself works.

For those, file a ticket with the engineering team.
