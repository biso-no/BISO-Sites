# Working with Appwrite

All Appwrite access goes through `@repo/api`. Never import `appwrite` or `node-appwrite`
directly in app code. See [Conventions](/docs/developing/conventions) for the why.

## Entry points

| Entrypoint | Use it for |
|---|---|
| `@repo/api/server` | Server-side: `createSessionClient()`, `createAdminClient()` |
| `@repo/api/client` | Browser-side: the user-facing Appwrite client |
| `@repo/api/page-builder` | Page editor draft/publish flow |
| `@repo/api` (root) | Runtime helpers: `ID`, `Query`, `Permission`, `Role`, `OAuthProvider`, `Models`, `TablesDB` |
| `@repo/api/types/appwrite` | Generated row types and enums |

## The two client factories

### `createSessionClient(jwt?)` — user-scoped

Respects per-row security. Reads the user's session cookie (or a passed-in JWT) and acts
as that user. **Use this for almost everything.**

```ts
import { createSessionClient } from "@repo/api/server";
import { Query } from "@repo/api";
import type { Pages } from "@repo/api/types/appwrite";

export async function getPublishedPages() {
  const { db } = await createSessionClient();
  return db.listRows<Pages>("app", "pages", [
    Query.equal("status", "published"),
    Query.orderDesc("$updatedAt"),
    Query.limit(20),
  ]);
}
```

### `createAdminClient()` — service key

Uses the server API key, bypasses row security. Use only for system tasks:
cron jobs, webhooks, migrations, role syncs. **Gate it behind your own auth check.**

```ts
import { createAdminClient } from "@repo/api/server";

export async function POST(req: Request) {
  if (req.headers.get("x-cron-secret") !== process.env.CRON_SECRET) {
    return new Response("Unauthorized", { status: 401 });
  }
  const { db } = await createAdminClient();
  // ... do system-level work
}
```

## The `db` proxy

`db` is not the raw `TablesDB`. It's a Proxy that JSON-clones `listRows` and `getRow`
results so they cross the React Server Component → Client Component boundary cleanly.

```ts
const { db } = await createSessionClient();

// ✅ Goes through the proxy — results are plain serializable objects
const events = await db.listRows<Events>("app", "events");

// ❌ Don't reach for the underlying TablesDB
// const events = await db.client.listRows(...); // breaks RSC serialization
```

If you ever get *"Objects with toJSON methods are not supported"* from React, you bypassed
the proxy.

## Queries

Use `Query` from `@repo/api`:

```ts
import { Query } from "@repo/api";

[
  Query.equal("campus_id", "oslo"),
  Query.notEqual("status", "archived"),
  Query.contains("tags", ["news"]),
  Query.search("title", "innovation"),
  Query.orderDesc("$createdAt"),
  Query.limit(25),
  Query.offset(0),
];
```

Full query reference: [Packages / `@repo/api`](/docs/packages/api).

## ACLs

Use `Permission` + `Role` from `@repo/api`. The string format is a footgun — let the
helpers compose it:

```ts
import { Permission, Role } from "@repo/api";

const perms = [
  Permission.read(Role.any()),                          // public read
  Permission.read(Role.team("admin")),                  // any admin
  Permission.update(Role.team("admin", "editor")),      // admin team, "editor" sub-role
  Permission.delete(Role.user(ctx.userId)),
];

await db.createRow<Pages>("app", "pages", ID.unique(), data, perms);
```

For content translations, use `buildContentTranslationPermissions()` (admin app) rather
than composing by hand:

```ts
import { buildContentTranslationPermissions } from "@/lib/utils";

const perms = buildContentTranslationPermissions(campusId, ctx);
```

## Campus scoping

This is the most common bug class on the platform. Any list query that returns
campus-owned data **must** be filtered to the campuses the user can see. The helper
lives in `apps/admin/src/lib/scope.ts`:

```ts
import { applyScopeQueries } from "@/lib/scope";

const queries = applyScopeQueries(ctx, [
  Query.equal("status", "published"),
  Query.orderDesc("$updatedAt"),
]);

const events = await db.listRows<Events>("app", "events", queries);
```

`applyScopeQueries` adds `Query.contains("campus_id", ctx.resolvedCampusIds)` (or the
right variant for the table) based on the user's role.

Cross-campus admins (IT, central staff) get the full set; campus-scoped editors get only
their own.

## Schema source of truth

- **Config**: `packages/api/appwrite.config.json` — collections, attributes, indexes,
  permissions. Auto-generated by the Appwrite CLI (`appwrite pull`). Don't hand-edit.
- **Types**: `packages/api/types/appwrite.ts` — generated row types and enums. Regenerate
  with `appwrite types -l ts ./types` from inside `packages/api`. Don't hand-edit.

Regen flow when the schema changes upstream:

```bash
cd packages/api
appwrite pull             # refresh appwrite.config.json
appwrite types -l ts ./types
bun run check-types       # from repo root, verify nothing broke
```

## Patterns

### List with pagination

```ts
import { Query } from "@repo/api";
import type { Events } from "@repo/api/types/appwrite";

const PAGE_SIZE = 20;

export async function listEvents(page = 0) {
  const { db } = await createSessionClient();
  return db.listRows<Events>("app", "events", [
    Query.orderDesc("$createdAt"),
    Query.limit(PAGE_SIZE),
    Query.offset(page * PAGE_SIZE),
  ]);
}
```

### Get-or-throw

```ts
export async function getEvent(id: string) {
  const { db } = await createSessionClient();
  const event = await db.getRow<Events>("app", "events", id);
  if (!event) throw new Error("Event not found");
  return event;
}
```

### Create with audit

```ts
import { ID, Permission, Role } from "@repo/api";

const row = await db.createRow<Events>(
  "app",
  "events",
  ID.unique(),
  {
    title: input.title,
    campus_id: ctx.activeCampusId,
    status: "draft",
  },
  [
    Permission.read(Role.team("admin")),
    Permission.update(Role.team("admin")),
  ]
);

await logAuditEvent({
  action: "event.create",
  actor: ctx.userId,
  resourceId: row.$id,
});
```

## Page editor: draft / publish

The block editor uses a separate flow via `@repo/api/page-builder` — see
[Adding an editor block](/docs/developing/adding-an-editor-block) and
[Packages / `@repo/editor`](/docs/packages/editor).

```ts
import { savePageDraft, publishPage } from "@repo/api/page-builder";

await savePageDraft({ pageId, document });
await publishPage({ pageId });
```
